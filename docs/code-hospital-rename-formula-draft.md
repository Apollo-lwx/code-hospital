## 1. 适应证：按「改名动作」分组枚举，不用前缀匹配

**前缀匹配（`N8` 一把抓）不可行**：同一前缀下的规则风险不同构——
`N999` 改的是文件名（等于文件移动，跨仓 import 全断），`N811–N817` 跟外部包名打交道，
`N804/N805` 贴着方法签名。前缀匹配的前提是同族规则同构，N 族不满足。
名册是数据不是代码，显式枚举几百条带组注释完全可维护；
前缀只留给确认同构的规则族（清创的 `I`、`UP`、`W` 就是这么用的）。

一期接 G1–G4，按组定风险与闭包：

| 组 | 改名动作 | 规则 | 闭包 | 一期 |
|---|---|---|---|---|
| G1 局部名字 | 函数内变量 / 参数 | `N803`、`N806` | 单函数，最小 | ✅ |
| G2 函数/方法名 | 定义 + 调用点 | `N802`、`N804`、`N805`、`N807` | 单文件 | ✅ |
| G3 类名 | 定义 + 引用 | `N801`、`N818` | 单文件 | ✅ |
| G4 模块级变量 | 全局 / 类作用域 | `N815`、`N816` | 单文件 | ✅ |
| G5 import 别名 | 本文件绑定名 | `N811`、`N812`、`N813`、`N814`、`N817` | 单文件，但涉及外部包语义 | ✅ 第二批已落地（2026-11-20） |
| G6 模块（文件）名 | 文件移动 | `N999` | 全仓 import 重写 | ❌ LSP 已到（2026-11-23），但文件移动与煎药管线结构性不兼容；移动剂型专项草案已出（code-hospital-move-formula-draft.md），拍板后接 |

**为什么只有这类规则能进**：改名入方的前提是「新名字有机械判据」。PEP 8 规定了
目标形态，宿主模型只做「现名 → 合规名」映射，不需要读懂业务语义。
误导性命名（`data` 装的是订单）这类需要读懂的，**永远不进正骨**——那是待复核的活。

**扩展路径**：新来源（ESLint `naming-convention`、Java 命名检查、仓库自己的命名约定）
进正骨前回答同一个问题——新名字有没有机械判据。有就按动作分组补进对应 G 组，
没有就留在待复核。规则清单变长是预期形态，不是问题。

**前提条件**：ruff 的 N 系列默认不开。发现只会在仓库 `code-hospital.yaml` 的
`catalog.rules.ruff_select` 显式启用 `N` 前缀后产生——名册里写明这条，
「没启用 N 系列」不是仪器缺席，是仓库没点这道菜。

## 2. 一期范围：单文件闭包

`scope: reference_closure` 一期降级为**单文件内改名**：

- 改名符号 + 同一文件内的全部引用一起改（同一处方项，一次煎药）；
- **跨文件引用不追**：符号被其他文件 import 时，该发现不入方，标待复核并写明
  「存在跨文件引用，等 LSP 符号级 scope（LSP001）」；
- 跨文件检测用现成的静态手段（本仓 import 文本扫描）即可，不需要真 LSP 才能守门。
  三期算法升级（2026-11-23）：匹配前用 tokenize 剥掉注释与字符串字面量
  （docstring 提一句符号名不算引用，误拦主力除根）；扫描被 `_SCAN_CAP` 截断
  改判「不能证明单文件闭包」堵漏拦——截断点之后查不到，放行就是漏。

这条收窄的理由：`reference_closure` 的全仓闭包在没有 LSP 时只能靠文本匹配，
误改率不可控；而单文件闭包可以用 AST 精确枚举引用点，风险与清创同级。

## 3. 规模：发现数超百怎么办

**不开一百味煎药。** 历史仓里几百处 `N802` 是**批量迁移**，不是诊疗：

- 诊断书把同规则、同文件的簇合成一个「批量迁移」病症（合并阈值建议 ≥20 处，
  写进名册阈值配置）；
- 开一味**外购（`manual`）**：建议用 codemod 一次性脚本迁移，处方项写明
  「迁移后该规则在本范围的发现数应为 0」作为验收口径；
- 出院随访的 CI 片段带上这条规则的复扫命令，回归有人看。

医院的价值在判定与验收，不在逐个改名。零散的几处（合并阈值以下）仍走正常煎药。

## 4. 剂型与风险

- **剂型 `llm_patch`（煎药）不变**；批量迁移项为 `manual`。没有可靠的机械改名
  执行器进入成药路径；ruff 不修命名，rope 这类重构库引入即破「主链路离线」原则。
- **状态 `advisory`（2026-11-23 三修订，四期泛化）**：正骨全组开方即落告知建议——告知用户
  「这里名字不合规」，但**做不做用户决定**，医院不自动施治。`_risk_level` /
  `_policy` / 确认文案只看 pending 项；药房只抓 pending 项；出院只拦 pending 项。
  用户的决定通道是 `hosp_prescribe` 的 `include_advisory`（点名药味 id 翻 pending，
  翻转先于风险核算，点名的项照样过自己的风险闸）。四期起该行为不再硬编码，
  由处置矩阵默认表（`N8*` → convention / never / explicit）驱动，仓库可用
  `catalog.rules.dispositions` 放宽或收紧（含把规范类拉成必须修）。
- **风险**：上限 `medium`，不升档（2026-11-23 二修订）——命名不合规是告知级事项，
  不进 user_required、不阻断流程。`touches_public_api`（导出符号、被 `__all__` 收录、
  或出现在包顶层 `__init__.py` 的再导出）不再升 `high`，改为在 instructions 写明
  「该符号是公开 API，仓外调用方不可见，改名后请自行评估影响」。
  G6（文件移动）真接上时另行评估。
- **伴随药**：对照（`contrast`）——改名后跑验收别名 `test`；主药挂起对照也挂起
  （同为 advisory），主药被点名翻 pending 时对照不自动跟翻（要连对照一起治就一起点名）。

## 6. 验收断言

| 断言 | 含义 |
|---|---|
| 未启用不触发 | 仓库未在 `ruff_select` 启用 N 前缀时，无任何正骨入方 |
| 组外不接 | `N999`（G6 模块文件名）的发现不入方，待复核并写明等 LSP |
| G5 别名局部 | import 别名不做跨文件守门直接入方；`__init__.py` 里的别名（重导出名）入待复核写明 LSP001 |
| 跨文件守门 | 符号被其他文件 import 的发现标待复核、不入方，诊断书写明原因 |
| 公开 API 不升档 | `__all__` 收录符号的正骨项保持 `risk=medium`（不进 user_required），instructions 写明仓外风险提示 |
| 单文件原子 | 一次施治的 diff 只触碰一个文件（符号定义 + 本文件引用） |
| 批量不煎药 | 同规则同文件 ≥ 阈值的簇合成一味 `manual` 批量迁移项，不出煎药 |
| 命名约定豁免 | 符号命中 `catalog.rename.exempt` 的发现不入方，待复核注明「命中命名约定」 |
| 告知不阻断 | 正骨项落 `advisory`：不抬处方风险、宿主代理可批、药房不抓、出院不拦 |
| 点名才施治 | `include_advisory` 点名的项翻 pending 并重新核算风险；未点名的项点名式抓药报「告知建议项」 |

## 7. 明确不做

- 不做误导性命名、缩写规范这类语义改名；
- 不做跨文件引用闭包（等 LSP001）；
- 不做成药路径（无机械执行器）；
- 不动 Java 侧改名（Java 语言科的正骨等 Java 成药执行器一起再议）。
